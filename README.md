# Дашборд операций: дорожный трафик FHWA (Power BI)

**English:** A Power BI Project (PBIP) dashboard on FHWA *Traffic Volume Trends*: monthly vehicle-miles travelled by US state, with a star schema (fact + date + state), Power Query transformations, 9 DAX measures and three report pages. Includes screenshots, an independent Python KPI re-check and documented limitations.

**За минуту.** Дашборд показывает, сколько миль проехали по дорогам США по месяцам и штатам, как меняется объём год к году и какие штаты и регионы дают основной вклад. Модель — «звезда»: `VMT` (факт), `DimDate` (календарь), `DimState` (штат и регион FHWA). Всё считается из официальных файлов FHWA; исходные данные и скрипт их сборки лежат в репозитории, поэтому цифры можно перепроверить.

| Показатель (32 месяца, 2024-01 … 2026-08) | Значение |
|---|---:|
| VMT за последние 12 месяцев (сен 2025 … авг 2026) | 3 331 842 млн миль |
| 12 месяцев к предыдущим 12 месяцам | **+0,6%** |
| Штатов в отчёте | 51 (50 штатов + округ Колумбия) |

Лидеры по объёму: California (873 614 млн, 9,9%), Texas (825 939 млн, 9,3%), Florida (648 470 млн, 7,3%).

## Источник данных

- **Источник:** FHWA, Office of Highway Policy Information — [Traffic Volume Trends](https://www.fhwa.dot.gov/policyinformation/travel_monitoring/tvt.cfm), ежемесячные отчёты (MS Excel), таблица 5 «Changes on ALL Estimated Roads by Region and State».
- **Права:** материалы федеральных агентств США (U.S. Government work) не охраняются авторским правом и находятся в общественном достоянии; ссылка на источник обязательна как вопрос академической честности, а не требования лицензии. Файлы FHWA не перепубликуются: в репозиторий попадают только производные CSV (штат × месяц × VMT), собранные скриптом.
- **Что взято:** месячный VMT по штатам (млн миль) за 2024-01 … 2026-08, 32 отчёта, 51 территория.
- **Как собрано:** `scripts/build_tvt_data.py` скачивает официальные XLSX, разбирает таблицу 5 и складывает три CSV: `traffic_vmt_monthly.csv`, `dim_state.csv`, `dim_date.csv`.

## Модель и меры

Схема «звезда»:

```
DimDate (date) 1 ── * VMT (month, state, region, vmt_millions, stations)
DimState (state) 1 ── * VMT
```

| Мера | Формула | Знаменатель / контекст |
|---|---|---|
| `Total VMT` | `SUM(VMT[vmt_millions])` | Сумма по всем строкам факта в текущем фильтре |
| `VMT L12M` | `CALCULATE([Total VMT], DATESINPERIOD(DimDate[date], MAX(VMT[month]), -12, MONTH))` | Последние 12 месяцев от последнего месяца с данными |
| `VMT Prev12M` | то же окно на 24 месяца назад минус `VMT L12M` | Предыдущие 12 месяцев |
| `VMT YoY %` | `DIVIDE([VMT L12M] - [VMT Prev12M], [VMT Prev12M])` | Сравнение двух полных 12-месячных окон |
| `VMT LY` | `CALCULATE([Total VMT], SAMEPERIODLASTYEAR(DimDate[date]))` | Тот же месяц год назад |
| `VMT YoY Month %` | `DIVIDE([Total VMT] - [VMT LY], [VMT LY])` | Месяц к тому же месяцу прошлого года |
| `Avg Monthly VMT` | `AVERAGEX(VALUES(DimDate[date]), [Total VMT])` | Средний месяц в текущем фильтре |
| `States Reporting` | `DISTINCTCOUNT(VMT[state])` | Число штатов, вернувших данные |
| `VMT Share` | `DIVIDE([Total VMT], CALCULATE([Total VMT], ALLSELECTED(DimState)))` | Доля штата в выбранных регионах |

Полное описание — [docs/measures.md](docs/measures.md), словарь данных — [docs/data_dictionary.md](docs/data_dictionary.md).

## Проверка

Независимый пересчёт тех же KPI на Python (без pandas и без DAX):

```powershell
python scripts\verify_kpis.py
```

Результат пишется в [reports/kpi_check.md](reports/kpi_check.md) и совпадает с дашбордом: 3 331 842 млн за 12 месяцев, +0,6% год к году, 51 штат, 276 143 млн в среднем за месяц.

## Запуск

1. Установите Power BI Desktop версии **2.157 или новее** (проект собран в 2.157.879.0, модель использует `compatibilityLevel: 1606`).
2. Откройте `TrafficOperations.pbip`.
3. Модель читает CSV из параметра `DataBase`: по умолчанию это публичный адрес папки `data` этого репозитория. Если загрузка из сети недоступна, укажите в «Преобразование данных → Изменить параметры» локальный путь к папке `data` (запросы поддерживают и `http`, и локальный путь).
4. Нажмите «Обновить» на ленте. **Это обязательный шаг:** проект PBIP не хранит данные внутри, поэтому до обновления визуалы показывают «(Пусто)». После обновления отчёт отрисуется на данных из `data/*.csv`.

**Если Desktop пишет «не поддерживает переход на более раннюю версию CompatibilityLevel»** — открыта старая копия проекта (в ней был уровень 1567) либо в кэше Desktop остался другой уровень. Скачайте актуальную версию из этого репозитория; если ошибка повторяется, закройте Desktop и удалите папку `%LOCALAPPDATA%\Microsoft\Power BI Desktop\AnalysisServicesWorkspaces`.

Пересобрать проект из исходников (детерминированно, с новыми lineage-тегами):

```powershell
python scripts\build_tvt_data.py
python scripts\generate_pbip.py
```

## Ограничения

- VMT — оценка FHWA по данным ~5 000 пунктов непрерывного учёта, а не сплошной подсчёт; значения уточняются задним числом, поэтому один и тот же месяц в разных выпусках может отличаться.
- Данные описательные: это не выручка, не стоимость и не загрузка дорог. Причин влияния на трафик здесь не измеряется.
- 2026 год неполный (январь–август), поэтому «последние 12 месяцев» — единственное корректное сравнение год к году; сравнение календарных лет было бы смещено.
- `stations` — число пунктов учёта, по которым отчитался штат: это показатель покрытия измерения, а не интенсивности движения.
- Скользящее окно 12 месяцев в начале ряда «наполняется» (первые месяцы окна неполные) — на графике это видно как рост в 2024 году.
- Дашборд не публиковался в Power BI Service: файл открывается локально в Power BI Desktop.
